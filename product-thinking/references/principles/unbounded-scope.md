**Claim.** Work with no fixed time box grows without limit, because nothing forces the team to choose what to cut.

## Why it is a problem
Shape Up sets an appetite first: the time the team wants to spend, decided before design. An estimate starts from a design and ends with a number, but an appetite starts with a number and shapes the design to fit. Singer says scope grows like grass, so the team must cut it all the time. A circuit breaker cancels work that does not ship in one six-week cycle instead of extending it. Getting Real makes the same rule: fix time and budget, and flex scope. Its "Hidden Costs" chapter shows how one small request, a meetings tab, pulls in locations, times, calendar sync, and help docs.

## How to detect
- Look for a deadline, milestone, or time box on the spec, epic, or roadmap item. Flag work with no end date.
- Check the spec for a must-have list and a nice-to-have list. Flag specs where everything is required.
- Compare the first version of the spec or epic with today. Flag items that grew without anything removed.
- Check the tracker for epics open longer than one or two cycles, or with repeated date changes.
- Flag vague tasks such as "redesign X" or "improve Y" with no concrete problem. Shape Up calls these grab-bags.
- Intake question: "How much time is this worth to you, before you would stop?"

## Fixes
- Set an appetite for each project, for example two weeks or six weeks. Shape the solution to fit it.
- Mark each task as must-have or nice-to-have. Cut nice-to-haves first when time runs short.
- If the work does not ship in the time box, stop it. Re-shape it before betting on it again.
