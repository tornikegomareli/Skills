**Claim.** Some ideas look easy and get praise from everyone, but many teams have already failed at them, and a new team that ignores that history fails the same way.

## Why it is a problem
YC partners Dalton Caldwell and Michael Seibel named the tarpit idea after seeing the same ideas apply again and again and fail. A tarpit is common, gets enthusiastic praise from friends, and has failed many times with nothing changed since. Their examples are restaurant discovery and apps to coordinate plans with friends. They name two common flavors: wishing the world worked differently when everyone would have to adopt the new way at once, and a quick-money arbitrage play. Seibel says new technology such as LLMs can reopen an old tarpit, but the founder must explain what changed. Paul Graham's list of startup mistakes calls local events a perennial tarpit.

## How to detect
- Read the README and spec. Check whether the idea is discovery or recommendation (restaurants, music, events), social planning with friends, or "do X with your friends".
- Search the docs for a section on prior attempts or competitors that failed. If there is none, flag it.
- Check whether the spec says what changed since earlier attempts: a new technology, a new channel, or a new regulation.
- Check whether value depends on many people adopting a new habit at the same time.
- Check whether the only validation is friends saying it is a great idea. If so, ask intake questions 1 and 7.

## Fixes
- List 3 to 5 earlier products in this space and why each one stopped. Use public post-mortems or shutdown notes.
- Write one sentence on what is different now. If you cannot, choose a different problem.
- Get one real user to use or pay for a rough version before more build work. Praise does not count.

## Cases
- `plancast-social-event-sharing` (failure)
- `color-labs-nearby-photo-network` (failure)
